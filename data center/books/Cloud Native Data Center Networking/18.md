# Validating Network Configuration（驗證網路配置）

* **引言哲學**：引用 Donald Knuth 的名言：*「Computers are good at following instructions, but not at reading your mind.（電腦擅長執行指令，但不擅長讀懂你的心思。）」*。
* **維運痛點**：網路自動化過往多停留在「配置發送（Provisioning）」，Day-2 的「狀態驗證（Validation）」仍大量依賴手動排查。
* **自底向上的驗證哲學 (Bottom-Up Validation)**：將抽象的「網路是否正常？」拆解為具體的「How-to」問題（如 BGP 狀態是否 Established、實體纜線是否插錯），並堅持由實體層（Cabling）至虛擬層（Overlay）由底向上逐層驗證，能在距離故障源最近處精確定位異常。

---

## 系統層級驗證 (System Validation)
* **條列重點與技術剖析**：
  * **驗證目標**：確認全網設備皆運行正確的網路作業系統（NOS）版本，且 CPU、記憶體、磁碟、晶片及系統服務均處於健康狀態。
  * **Linux 與傳統 NOS 檢測**：Linux 原生系統可透過 `hostnamectl` 查看 OS 與 Kernel 版本；Ansible 則自動透過 Facts（如 `ansible_distribution` 或 `eos_facts`）提取設備資訊。
  * **Ansible 自動化宣告 (`assert`)**：在 Playbook 中定義 `expected_version` 變數（如 Cumulus `3.7.6` 或 Arista EOS `4.22.0F`），利用 `assert` 模組自動比對全網設備版本是否一致。

---

## 線路與實體拓撲驗證 (Cabling Validation)

* **條列重點與技術剖析**：
  * **核心問題**：驗證 Leaf 與 Spine 之間是否嚴格遵循 Clos 拓撲的全互連（Full-Mesh）規範，排除線纜錯拔或單向鏈路故障。
  * **LLDP 協定與 `lldpd`**：推薦採用開源的 `lldpd` 套件（搭配 `lldpctl` 指令），能以標準格式輸出鄰居的 ChassisID、SysName、PortID 及鏈路能力。
  * **PTM (Prescriptive Topology Manager)**：過往 Cumulus 提出的拓撲驗證工具，採用 **DOT 語言** 定義預期拓撲，比對實時 LLDP 狀態。



## 介面配置驗證 (Interface Configuration Validation)

* **條列重點與技術剖析**：
  * **核心驗證清單**：
    1. **全網 MTU 一致性**（防止 VXLAN 50-byte 標頭引發分段）。
    2. **VLAN 與 IP 子網匹配**（具號介面需確保兩端同子網）。
    3. **VRF 劃分正確性**。
    4. **MLAG / CLAG 雙歸狀態**（System ID、Peer-Link 狀態、MLAG-ID 是否對齊）。
  * **FRR 介面檢測指令 (Example 18-5)**：
    * `sudo vtysh -c "show interface vrf all brief"`：快速列出所有 VRF 下的介面摘要。
    * `sudo vtysh -c "show interface <ifname>"`：詳細檢視單一介面的 MTU、Speed、Master 綁定關係及 IPv6 RA 宣告狀態。
  * **Ansible 介面自動化驗證**：調用 `ansible_lo.ipv4_secondaries` 驗證 Loopback 是否配置私有 IP，並跨對等節點比對 `ansible_{{item}}.mtu` 是否完全一致。

## 路由協定配置驗證 (Routing Configuration Validation)

* **通用路由驗證要點**：Router ID（應取 Loopback IP）、Loopback 路由宣告、對等鄰居建立狀態，以及外網預設路由 (`0.0.0.0/0`) 的發布者追蹤。

#### 1. OSPF 配置驗證 (Validating an OSPF Configuration)
* **排查指令與狀態**：
  * `show ip ospf neighbor`：確認鄰居狀態是否達到 **`Full`**（非 P2P 網段顯示 `Full/DROther`）。
  * `show ip ospf interface`：確認介面是否設為 **`POINTOPOINT`**（避免無謂的 DR/BDR 選舉），並檢查是否正確啟用 `Unnumbered`。
* **故障診斷 (MTU 不匹配)**：若狀態卡在 `ExStart` 或 `Exchange`，利用 `journalctl -n -p 0..4 -u frr` 能精確抓出 `MTU 9216 is larger than MTU 1500` 的致命錯誤。
* **OSPF 自動化劇本**： Ansible 透過 `vtysh -c "show ip ospf int json"` 抓取 JSON，驗證 `ifUp` 為 true、`nbrCount == nbrAdjacentCount` 且 `networkType == 'POINTOPOINT'`。

## 網路虛擬化與 EVPN 驗證 (Validating Network Virtualization)

* **條列重點與技術剖析**：
  * **核心檢測項目**：
    1. 所有 L2/L3 VNI 是否正常發布？
    2. 對稱式路由的 L3 VNI 與 Tenant VRF 映射是否正確？
    3. 實體 VTEP IP 是否在 Underlay (Default VRF) 中順利宣告？
    4. 全網 BUM 流量處理模式（Ingress Replication / 頭端複製）是否一致？
* **EVPN 專屬檢測指令**：
  * `show bgp l2vpn evpn vni`：顯示全網 VNI 狀態、BUM 轉發模式 (Head-end replication) 以及已知 L2/L3 VNI 數量。
  * `show bgp l2vpn evpn vni <VNI>`：檢視特定 VNI（如 L3 VNI `104001`）對應的 Tenant VRF (`evpn-vrf`)、RD (`10.2.4.11:4`) 與 Import/Export Route Targets (`65011:104001`)。

  * `show evpn`：印出重複 IP/MAC 位址檢測 (Duplicate Address Detection) 參數。
* **EVPN 自動化劇本**：Ansible 提取 `show bgp l2vpn evpn vni json`，驗證 `advertiseAllVnis == "Enabled"`、跨 VTEP 查詢 `/32` VTEP IP 路由均可達，並驗證全網 VTEP 的 `numRemoteVteps` 與 `flooding` 參數完全一致。

## 應用程式層級網路驗證 (Application’s Network Validation)

* **條列重點與技術剖析**：
  * **端到端路徑 MTU 探測**：應用層連通性是資料平面的最終試金石。在使用 VXLAN 隧道時，必須帶上禁止分段（Don't Fragment）標記進行巨型封包（Jumbo Frame）測試：
    `ping -s 9000 -M do <IP_Destination>`。
  * **ECMP 負載分流雜湊觸發**：若要讓單一主機測試多條 ECMP 上鏈路徑，需在 Linux 核心開啟四元組/五元組多路徑雜湊策略：
    `sudo sysctl -w net.ipv4.fib_multipath_hash_policy=1`。

## 資料平面驗證 (Data-Plane Validation)

* **原生 Linux vs. FRR 資料平面查詢指令對照表**：

| 資料平面表項 (Data-Plane Table) | 原生 Linux 命令列 (iproute2 / bridge) | FRR CLI 整合指令 (vtysh) |
| :--- | :--- | :--- |
| **MAC 位址轉發表 (FDB)** | `bridge fdb show [vlan <VLAN>]` | `show evpn mac vni <VNI\|all> [detail]` |
| **特定 VTEP 的 MAC 表** | `bridge fdb show \| grep <VTEP_IP>` | `show evpn mac vtep vni <VNI> <VTEP_IP>` |
| **三層路由轉發表 (FIB)** | `ip route show [vrf <VRF_Name>]` | `show ip route [vrf <VRF_Name>]` |
| **全網 VRF 路由總表** | `ip route show table all` | `show ip route vrf all` |
| **ARP / ND 快取表** | `ip neighbor show` | `show evpn arp-cache [vni <VNI>]` |
