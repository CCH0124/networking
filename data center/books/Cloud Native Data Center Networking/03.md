# Network Disaggregation
## What Is Network Disaggregation?

* **定義與概念**：
    * **軟硬體分離**：傳統網路設備（如 Cisco、Juniper）將硬體與網路作業系統 (NOS) 深度整合綁定銷售。網路解耦則是將交換器/路由器的**硬體 (Hardware)** 與 **軟體/網路作業系統 (NOS)** 解耦，允許使用者各自向不同廠商獨立採購。
    * **歷史對照（伺服器解耦的韻腳）**：此趨勢類似於 20 年前伺服器領域從 Sun (Sparc + Workstation + Solaris) 等垂直整合微型電腦，轉向通用 x86 硬體 + Linux/Windows 作業系統的「伺服器解耦」過程。

* **交換器組件拆解模型**：
    * **硬體層 (Hardware)**：包含封包交換晶片 (Packet-Switching Silicon / ASIC)、CPU 控制單元 (x86 / ARM)、實體機箱 (Box)、光纖模組 (Optics) 與線纜。
    * **軟體層 (Software)**：包含基礎作業系統（如 Linux Kernel）與控制平面應用程式（包含 Routing Suite 如 FRR、組態與監控 Agents）。

## Why Is Network Disaggregation Important?

* **控制資本與營運成本 (CapEx &amp; OpEx Control)**：
    * **打破光模組壟斷**：傳統廠商常鎖定專有光模組與線纜並收取高達 10–20 倍的溢價；解耦後可自由採購標準化第三方光模組與線纜。
    * **降低維運自動化阻礙**：借助 Linux 原生生態系與自動化工具（如 Ansible），大幅降低大規模機房的營運成本 (OpEx)。
* **避免廠商鎖定 (Avoiding Vendor Lock-In)**：
    * 採用開源或標準化的 Linux 作業系統 (NOS)，避免被單一傳統廠商的私有指令集與協定鎖定。
* **功能與晶片標準化 (Standardization of Features)**：
    * 避免過度依賴廠商私有的 ASIC 功能（如 FabricPath、OTV 等），轉而專注於開放標準協定（如 IP 路由與 BGP）。

## What Made Network Disaggregation Possible Now?

**三大驅動要素**：

1. **大規模數據中心營運商的推動**：Web-scale 業者（如 Meta、Google）不滿傳統廠商更新緩慢且維運封閉，開始自行定義硬體規格。
2. **Clos (Leaf-Spine) 拓撲的普及**：全面改用純 L3 路由的 Leaf-Spine 架構，摒棄了傳統 Access-Agg 複雜的 L2 橋接與 STP 私有擴充，大幅簡化了 NOS 所需的功能集。
3. **商用交換晶片 (Merchant Silicon) 的崛起**：Broadcom、Mellanox 等獨立晶片商提供高效能、高埠數且具備新特性（如 VXLAN）的商用 ASIC，效能與功能不再落後於傳統廠商自研晶片。

> [!TIP]
> A network switch without a NOS is also called a bare-metal switch, using the term "baremetal" differently from the concept behind bare-metal servers.

## Difference in Network Operations with Disaggregation & Open Network Installer Environment

* **白牌機 (White-Box) 與 品牌白牌機 (Brite-Box)**：
    * **White-Box (白牌交換器)**：由原廠設計製造商 (ODM，如 Edgecore, Quanta, Celestica) 生產的無品牌裸機 (Bare-Metal Switch)。
    * **Brite-Box (Branded White-Box)**：由傳統大廠（如 Dell）提供硬體，但允許客戶挑選安裝第三方 NOS（如 Cumulus Linux）。
* **首次開機自動化：ONIE (Open Network Installer Environment)**：
    * **背景與痛點**：裸機交換器出廠時未預裝 NOS，且各 ODM 硬體設計微小差異多，缺乏像 PC 時代 IBM 的統一參考設計。
    * **ONIE 的定位**：由 Cumulus 開發並由 OCP (Open Compute Project) 採納的開源 Bootloader，以小型 Linux + Busybox 為基礎。
    * **運作機制**：開機後，ONIE 會透過 DHCP、DNS-SD、HTTP 或 TFTP 自動尋找並下載 NOS 安裝映像檔 (Installer Image)，實現零觸碰自動化部署 (Zero-Touch Provisioning)。
    * **可安裝的 NOS 範例**：Cumulus Linux、SONiC、OpenSwitch、FBOSS 等。

#### ONIE (Open Network Installer Environment) 核心運作機制

1. **架構基礎與核心組件 (Core Architecture)**
   * **Linux Kernel + Busybox 輕量化環境**：ONIE 本質上是一個小型的 Linux 發行版（採用 Linux Kernel，例如 4.9.95 版）搭配 **Busybox** 運作環境。Busybox 整合了許多精簡版的 UNIX 命令列工具，讓系統管理員或安裝腳本能運用標準 Shell Script 自動化控制整個安裝與開機流程。
   * **架構獨立性 (Chipset-Independent)**：相較於伺服器領域僅支援 x86 的 PXE，或 ARM/PowerPC 專用的 u-boot，ONIE 設計宗旨在於跨越硬體 CPU 架構，提供一套通用於 **x86、PowerPC 及 ARM** 等多種處理器的單一 Installer。
   * **豐富的網路與儲存支援**：由於 ONIE 本身就是 Linux，因此原生支援 IPv4、IPv6、HTTP、TFTP 等網路協定，以及各類本地儲存媒體，能靈活取得 NOS 安裝映像檔。

2. **管理介面與硬體隔離 (Management Interface Isolation)**
   * **僅存取 Out-of-Band (OOB) 管理埠**：ONIE 進行網路通訊時，**僅會使用交換器上的 Management Ethernet Port**（由 Linux 內核中的標準乙太網路驅動程式驅動）。
   * **繞過交換晶片 (Switching Silicon)**：ONIE 完全不會載入或使用主交換晶片（如 Broadcom ASIC）的專用驅動程式。這是因為交換晶片驅動過於龐大，且在安裝系統階段完全沒有必要，藉此維持了 Bootloader 的極致輕量與穩定。

3. **啟動時機與尋送搜尋順序 (Discovery Order & Probing)**
   * **啟動條件**：ONIE 僅會在「交換器未安裝任何 NOS」或「已安裝的 NOS 明確設定讓 ONIE 再次運行」時才會觸發；一旦 NOS 安裝完成，系統重開機後便會直接進入 NOS。
   * **映像檔尋找優先順序 (Search Order)**：
     1. **本地端 USB 隨身碟** (Local USB flash drive)
     2. **DHCP 伺服器回應之 URL** (URL from the DHCP server)
     3. **DNS 服務發現** (URL obtained via DNS Service Discovery)
     4. **IPv4 / IPv6 Link-Local 鄰居探測** (Probing over IPv4/IPv6 link-local neighbors)
     5. **HTTP 探測** (Probing over HTTP)
     6. **TFTP 探測** (Probing over TFTP)
   * **探測與故障重試機制**：探測時，ONIE 會向 `255.255.255.255` (IPv4) 或 `ff02::1` (IPv6) 發送 ping/ping6 獲取本地鄰居 IP，並比對多組預設檔名。若某個管道安裝失敗，ONIE 會自動降級至下一個方法，並保持無限循環，直到成功安裝 NOS 為止。

4. **環境變數注入與 ZTP 自動化 (Environment Variables Setup)**
   * **自動提取設備上下文**：在執行 NOS 安裝腳本前，ONIE 會自動設置一系列系統環境變數，包括**主機名稱 (Host Name)、交換器序列號 (Serial Number) 以及 廠商識別碼 (Vendor ID)** 等資訊。
   * **精準安裝策略**：NOS 的安裝腳本可直接讀取這些 ONIE 變數，據以自動決定下載適合該 Switch 型號或 CPU 架構的確切 OS 映像檔，達成零觸碰自動化部署 (Zero-Touch Provisioning)。

5. **系統自我更新能力 (Self-Update Mechanism)**
   * **韌體升級機制**：ONIE 亦能透過相同的下載流程來更新自身。只需將目標檔案指定為「新版 ONIE 韌體映像檔」（而非 NOS 映像檔），即可完成 ONIE Bootloader 的自我升級。
