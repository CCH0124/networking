# Routing Protocol Choices
## 路由基本原理與運作流程 (Routing Overview &amp; How Routing Works)

* **路由定義與自主決策 (Routing Overview)：** 單播路由 (Unicast Routing) 是雲端原生資料中心的基礎賦能技術。IP 路由要求每台路由器獨立進行單播封包轉發決策（只關注到達最終目的地的下一跳 Next-Hop），這種本地化的決策優勢讓 IP 網路機能在故障發生時迅速繞過故障點

* **單播封包轉發五大步驟 (Steps of Routing)：**
    1. 在路由表中搜尋封包的目的 IP 位址，取得下一跳 (Next-Hop) 條目清單。
    2. 自下一跳清單中選出一個最優下一跳。
    3. 查詢 ARP/NDP 表格，確定該下一跳的實體 MAC 位址。
    4. 更新封包與影格標頭（包括改寫目的 MAC 位址與遞減 IP 標頭的 TTL）。
    5. 將封包由選定的網路介面發送出去。

* **最長前綴匹配原則 (Longest Prefix Match, LPM)：** 路由表以 IP 位址前綴 (Prefix) 作為鍵值 (Key)，這允許將多個連續 IP 位址聚合為單一路由條目以縮減表格規模。當有多個匹配的前綴時，系統會嚴格依據匹配位元數最長的「最長前綴匹配原則」選出正確的轉發路徑

* **路由終止與 ICMP 錯誤處置：** 當封包抵達目的網段時，路由器透過 ARP (IPv4) 或 NDP (IPv6) 取得目的主機 MAC 並完成交付。若無可用路由或遭遇傳輸錯誤，封包會被直接丟棄並回傳 ICMP 錯誤訊息

## 路由表項分類與 RIB vs. FIB 運作機制 (Types of Entries, RIB and FIB)

**三種路由表項來源 (Types of Routing Table Entries)：**

    1. **直連路由 (Connected Routes)：** 網路協定棧在介面配置 IP 位址時自動產生的網段路由，無須路由協定即可與直連鄰居通訊。
    2. **靜態路由 (Static Routes)：** 管理員手動配置的路由，優先權高於動態路由協定，當下一跳介面失效時會標註為不可用。
    3. **動態路由 (Dynamic Routes)：** 由路由協定（如 BGP、OSPF）或 DHCP 在計算最短路徑後自動填入的路由。

**控制平面 RIB 與資料平面 FIB 的分工：**
    * **RIB (Routing Information Base)：** 隸屬於控制平面軟體，收集由直連、靜態與各動態路由協定傳入的所有可能路徑。RIB 管理器依據**管理距離/優先距離 (Distance)** 選擇最優路由（Distance 越小越優先，如直連 < 靜態 < OSPF = 110）。

    * **FIB (Forwarding Information Base)：** 隸屬於資料平面 (Data Path)，僅儲存 RIB 管理器篩選出的「勝出條目 (Winning Entries)」，專供資料晶片進行極速封包轉發。

    * **Routing Loops (路由迴圈)：** 若網路拓撲設計不良或路由協定收斂緩慢，可能導致封包在兩台以上路由器間無限循環，造成頻寬浪費與 CPU 負擔。標準 IP/OSPF 網路通常在路由標頭中設有 TTL (Time To Live) 欄位，當 TTL 歸零時封包會被丟棄，以此作為防範路由迴圈的基礎機制。

**Linux Kernel 的 FIB 與介面參數：** 在 Linux 系統中，`ip route show` 輸出的是 Kernel 的 **FIB**。其中包含 **metric**（同一距離下選擇數值較低者）與 **weight**（用於多路徑 ECMP 時的流量分配比例，預設權重相同）等核心控制參數

## 距離向量 (DV) 與 鏈路狀態 (LS) 協定之深度對比 (Distance Vector vs. Link-State)

* **訊息傳播哲學的本質差異 (Core Difference)：**
    * **距離向量 (Distance Vector, DV - 如 BGP, RIP, EIGRP)：** 路由器僅向直連鄰居通告其到達各目的網段的「距離成本 (Distance)」，不透漏拓撲細節。俗稱「路由器與鄰居八卦全網的事 (Gossips about everybody with its neighbors)」。
    * **鏈路狀態 (Link-State, LS - 如 OSPF, IS-IS)：** 路由器向全網氾濫廣播 (Flooding) 其直連鄰居的「鏈路狀態 (LSA)」，訊息不經修改。各節點取得相同的全網拓撲地圖後，各自獨立運行 SPF 演算法計算最短路徑。俗稱「路由器與全網八卦其鄰居的事 (Gossips about its neighbors with everybody else)」。

* **擴展性與分層 (Scaling)：** DV 協定會在傳遞過程中自動合併資訊；而 LS 協定為了避免 LSA 記憶體與訊息氾濫爆表，必須引入 **Area (OSPF)** 或 **Level (IS-IS)** 的分層架構，在跨區域時退化為類似 DV 的行為。現代 x86 CPU 運行 FRR/IS-IS 可輕鬆支援單一 Area 達數百甚至 1,000 個節點。
* **等價多路徑 (ECMP) 與增量 SPF (Incremental SPF)：** 在 Clos 拓撲中，兩種協定最終選出的 ECMP 路徑效率相同。當鏈路發生與自身無關的故障時，DV 協定無須重新計算，而 LS 協定則透過「增量 SPF (Incremental SPF) 演算法」來避免重新計算整棵最短路徑樹。
* **多協定支援 (Multiprotocol Support)：** BGP 與 IS-IS 原生具備強大的多位址族群 (Multi-Address Family) 擴展能力，能同時傳遞 IPv4、IPv6、MPLS 與 EVPN MAC 位址；OSPF 則需升級為不可相容的 OSPFv3 才能支援 IPv6

### DV 與 LS 協定之多維度特性比較

* **擴展性與階層切分 (Scaling &amp; Hierarchy)：**
    * DV 協定會在傳遞過程中自動合併資訊，天然具備極高擴展性。
    * LS 協定為了防止全網 LSA 記憶體爆表與 Flooding 訊息風暴，必須引入階層化切分——**Area (OSPF)** 或 **Level (IS-IS)**。
    * 在跨越 Area/Level 時，LS 協定會退化為類似 DV 的行為。現代 x86 CPU 運行開源協定套件 (FRR) 時，單一 Area 已能輕鬆支援 384 至 1,000 個節點。
* **等價多路徑 (ECMP) 與增量 SPF (Incremental SPF)：**
    * DV 與 LS 協定在 Clos 拓撲中計算出的 ECMP 效率完全相同。
    * **無新聞即是好新聞 (No News Is Good News)**：當遠端鏈路故障但不影響本地選路時，DV 協定完全不發送更新；而 LS 協定仍會收到 LSA 通告。現代 LS 實作皆採用**增量 SPF (Incremental SPF)** 演算法，避免重新計算整棵最短路徑樹，巨幅降低 CPU 負擔。
* **收斂速度與傳播延遲 (Convergence Speed)：**
    * LS 協定因 LSA 原封不動地廣播，訊息傳播極快，各節點可平行運行 SPF，收斂理論上較快。
    * DV 協定需逐跳計算後才能再向外通告，且可能包含 Hold-down 定時器以防 Count-to-Infinity 問題。但**在資料中心內適當調校定時器後，BGP 的收斂速度完全不亞於 LS 協定**。
* **多位址族群支援 (Multiprotocol Support / AFI/SAFI)：**
    * BGP 與 IS-IS 原生支援多位址族群 (Multiprotocol)，能在單一會話中同時傳遞 IPv4、IPv6、MPLS 及 EVPN MAC 位址。
    * OSPF 則需要升級為互不相容的 OSPFv3 才能支援 IPv6，多協定擴展能力較弱。

## 無 IP 介面技術 (Unnumbered Interfaces) 的革命性突破

* **傳統具號介面 (Numbered Interfaces) 的痛點：** 傳統做法需為每條路由器間的點對點鏈路分配獨立的 IP 位址（如 `/30` 或 `/31`）。這不僅增加了 FIB 表格負擔與潛在攻擊面，更大幅增加了自動化腳本配置 IP 的複雜度與接線錯誤風險。

* **無號介面 (Unnumbered Interfaces) 的運作機制：** 介面本身不配置獨特的 IP 位址，而是「借用」路由器上永遠存活的 **Loopback 介面 IP**。在 Clos 拓撲中，相鄰層級間多採單一鏈路，無號介面能極大地簡化自動化部署。

* Unnumbered BGP 的創新
    * OSPF/IS-IS 原生支援多播 Link-Local 鄰居搜尋；但 BGP 傳統上依賴 TCP 179 通訊，需要直連網段或 IP 路由。
    * Dinesh Dutt 與 Cumulus 團隊研發了 **Unnumbered BGP**：利用 **IPv6 Link-Local Address (LLA,** **fe80::** **)** 自動建立 TCP 鄰居，並透過 **RFC 5549** 規範，在 BGP MP_REACH_NLRI 中通告「以 IPv6 LLA 作為下一跳的 IPv4 路由」。這徹底排除了介面 IPv4 位址的配置需求，成為現代資料中心自動化的黃金標準。  

## Clos (葉脊) 拓撲中的路由協定行為與收斂性 (Routing Protocols in Clos Networks)

* BGP 在 Clos 拓撲中的 ASN 規劃與自頂向下路由 (Top-Down Routing)：
    * **ASN 分配模型：** 每台 Leaf 配置獨立 ASN；同一 Pod 內的所有 Spine 配置相同 ASN；全網 Super-Spine 配置相同 ASN
    * **消除路徑搜尋 (Path Hunting) 與防環：** 此模型實現了「自頂向下路由 (Top-Down Routing)」，同層級設備（如 Spine 間）因相同 ASN 會觸發 BGP BGP 防環機制而自動丟棄更新。當 Leaf-Spine 鏈路中斷時，撤銷訊息僅局部傳播，不會向全網引發 Path Hunting 震盪。
* **鏈路狀態 (LS) 協定在 Clos 中的缺點：** 在 OSPF/IS-IS 下，Pod 內任何單一鏈路中斷，其 LSA 均會廣播漫延至整個 Pod 與 Backbone Area，引發全網所有路由器同步重新執行 SPF 計算，收斂開銷顯著高於 BGP。

## 路由摘要 (Route Summarization) 與安全防護 (Security & BFD)

* **路由摘要位置約束 (Leaves Only, Not Spines)：** 在 Clos 網路中，**路由摘要只能在 Leaf (ToR) 設備上執行，絕不能在 Spine 設備上摘要**。若 Spine 做了網段摘要，當某台 Leaf 斷線時，Spine 仍會繼續吸引該網段流量，進而造成流量黑洞或在 Spine/Leaf 間無休止地迴圈對彈。
* **路由過濾 (Route Filtering) 安全屏障：** 隨著 Kube-router 與 Calico 將 BGP 推進至 Host 伺服器端，必須透過 Route-Maps 或 Prefix-Lists 實施嚴格的進/出站路由過濾，防止伺服器端誤宣告非法前綴導致全網癱瘓。
* **雙向轉發偵測 (BFD, RFC 5880/5881)：** BFD 是一種獨立於特定路由協定的微秒級故障偵測機制。它能精準捕捉單向光纖故障或晶片半死卡死等隱蔽異常，讓 OSPF/BGP 能維持較鬆散的 Keepalive 定時器，將極速收斂的重擔交由 BFD 處理。

## 資料中心路由協定選型指南 (Choosing the Protocol)

* 資料中心路由協定需求階層：
    * 基礎需求： 支援 IPv4/IPv6 前綴分發、快速收斂、支援 Node Maintenance 流量優雅撤回 (Max-Metric/Overload bit)、自動化友善。
    * 進階需求： 支援多協定/網路虛擬化 (EVPN)、支援萬級大規模節點、支援在 Host 伺服器 (Calico/Kube-router) 上執行、協定數量盡可能極簡。
* 協定選型決策樹 (Protocol Decision Matrix)：
    * 若需要支援 EVPN 網路虛擬化 $\rightarrow$ 唯一解答：BGP。
    * 若需要與 Host 伺服器/容器對等 Peer $\rightarrow$ 唯一解答：BGP。
    * 若僅需純 IPv4 單播且規模小於 32,000 條路由 $\rightarrow$ OSPFv2 為可行備選。
* 路由協定之禪 (Zen of Routing Protocols)：
    * Simple is better than complex. (簡單勝於複雜)
    * One is better than many. (單一協定勝於多重協定，優先選 eBGP 單一協定貫穿 Underlay/Overlay)
    * Unnumbered is better than numbered. (無號介面勝於具號介面)
