# The Motivations for a New Network Architecture

核心探討**應用程式架構的演進**如何倒逼**網路底層拓撲**進行根本性的變革。


### 應用程式與網路的演進推移 (The Application-Network Shuffle)

網路架構的設計永遠是由上層應用程式的通訊模式所驅動：

*   **單體應用程式時代 (Single Monolithic Apps)**：
    *   執行於大型主機 (Mainframe)，採用專有硬體與傳輸協定（如 SNA、DECnet）。
    *   對網路頻寬的需求極低。
*   **用戶端-伺服器時代 (Client-Server Architecture)**：
    *   工作站與 PC 普及，區域網路 (LAN) 興起。
    *   乙太網路 (Ethernet) 與 TCP/IP 逐漸擊敗了 Token Ring、FDDI 以及 Novell IPX / Banyan VINES 等專有協定，奠定了現代網路的基礎，傳輸速率提升至 Gigabit Ethernet。
*   **網際網路與三層式架構 (Web & 3-Tier Architecture)**：
    *   伺服器拆分為 Web 前端、應用程式 (App) 與資料庫/儲存 (DB/Storage)，並透過負載平衡器 (Load Balancers) 進行前端分流。
*   **伺服器虛擬化 (Server Virtualization)**：
    *   為解決 CPU 多核心運算資源的浪費，虛擬機器 (VMs) 廣泛應用於企業，使單一實體主機上能執行多個隔離的虛擬單元。
*   **搜尋引擎與分散式叢集 (Web Search & MapReduce)**：
    *   以 Google 為代表的巨量搜尋與 MapReduce 等叢集計算崛起，促成了網路流量模式的**歷史性轉變——從傳統「用戶端-伺服器 (North-South, 南北向)」流量為主，轉變成以「伺服器對伺服器 (East-West, 東西向)」流量佔絕對主導地位**。
*   **微服務、容器與雲端原生 (Microservices, Containers & Cloud)**：
    *   遵循 Unix 設計哲學，微服務將應用拆分得更小，輕量化的容器 (Containers) 迅速取代 VM。
    *   雲端基礎設施 (Cloud) 支援的租戶與連線規模遠超傳統企業，驅動鏈路頻寬從 10GbE 一路跨越至 400GbE。

### 世紀之交的傳統網路設計：Access-Aggregation-Core (The Network Design from the Turn of the Century)

世紀之交流行的傳統資料中心網路稱為 **Access-Aggregation-Core 架構（簡稱 Access-Agg-Core 或 Access-Agg）**：

*   **分層架構**：
    *   **Access（存取層）**：終端伺服器連接至 Access 交換器。
    *   **Aggregation（聚合/分發層）**：Access 交換器雙上鏈連接至一對 Aggregation 交換器，提供冗餘。
    *   **Core（核心層）**：Aggregation 交換器再上連至 Core 骨幹。
*   **二層 (L2) 與三層 (L3) 的邊界**：
    *   Agg 交換器南向（面向 Access）採用 **L2 橋接 (Bridging)** 轉發；北向（面向 Core）採用 **L3 路由 (Routing)** 轉發。
*   **當時採用 L2 橋接的推動力**：
    1.  **硬體 ASIC 切換的崛起**：早期硬體 ASIC 交換晶片延遲極低、埠數多，但初期**僅支援 L2 橋接**。
    2.  **相容多種專有 L3 協定**：當時企業網包含 IPX、AppleTalk 等多種 L3 協定，L2 橋接能在不關心 L3 協定的情況下提供統一傳輸。
    3.  **零組態 (Zero Configuration) 的承諾**：透明橋接（Self-learning transparent bridges）具備 MAC 地址自動學習能力，省去了當時極為複雜的 IP 路由配置。
*   **傳統 L2 網路的補救協定**：
    *   **生成樹協定 (Spanning Tree Protocol, STP)**：解決 L2 標頭缺少 TTL 欄位所導致的廣播風暴 (Broadcast Storms)。STP 將拓撲剪枝為無環樹，但會阻斷 Access 到 Agg 之間的一條鏈路，導致**可用頻寬直接折半 (Active-Standby 模式)**。
    *   **虛擬區域網路 (VLAN)**：為解決過度廣播/多播（如 NetBIOS、ARP）噪音，將實體網切割為多個邏輯廣播域。
    *   **第一跳路由器備援 (FHRP)**：在 Agg 交換器上實施 HSRP/VRRP，確保 Default Gateway 在 Agg 設備故障時可切換。
    *   **在線軟體升級 (ISSU)**：採用 Active-Passive 雙控制板進行狀態同步以期實現無感升級，但因軟體極度複雜反而常引發非預期故障。

### Access-Aggregation-Core 架構的痛點與失敗原因 (The Trouble with Access-Agg-Core)

當東西向 (East-West) 流量爆發與超大規模 (Web-scale) 需求到來時，Access-Agg 架構展現出嚴重的系統缺陷：

1.  **不可擴展性 (Unscalability)**：
    *   **淹沒與學習模型 (Flood & Learn) 失效**：MAC 地址無法進行路由聚合。在數百萬個虛擬端點 (VM/Container) 環境下，頻繁的廣播淹沒與 MAC 表逾時重學會直接癱瘓實體主機與 Hypervisor。
    *   **VLAN 數量瓶頸**：傳統 12-bit VLAN ID 僅支援 4,096 個網段，遠不足雲端多租戶需求；若擴展為 24-bit VLAN，執行 1,600 萬個 STP 實例在系統上完全不可行。
    *   **ARP 負擔過重**：兩台 Agg 交換器需回應全網所有主機的 ARP。如 Windows Vista 調整 ARP 刷新時間至 15 秒或虛擬端點數量暴增，會直接打爆 Agg 交換器的 CPU，引發連鎖控制協定中斷與全網崩潰。
    *   **頻寬受限於 2 台 Agg 交換器**：STP 的限制使 Access 交換器最多只能上連至 **2 台** Agg 交換器，無法透過擴充 Agg 交換器數量來橫向擴充東西向頻寬，導致嚴重的網路壅塞。
2.  **系統複雜性 (Complexity)**：
    *   堆疊了多種複雜且相互干擾的協定（STP 及其衍生版、FHRP、VTP、ISSU 等），維運與故障排查極其困難。
    *   路徑中任何一台中間設備未正確配置 VLAN，就會導致網路切割 (Partition)。
    *   兩台 Agg 交換器之間的 Peer Link 頻寬規劃困難；單條上鏈故障易導致流量轉向 Peer Link，引發意外的效能下降。
3.  **粗顆粒的故障域與巨大爆炸半徑 (Coarse-grained Failure Domain & Large Blast Radius)**：
    *   單一鏈路或單台 Agg 交換器故障，會**瞬間失去全網 50% 的可用頻寬**。
    *   存活下來的單台 Agg 交換器必須獨自承載雙倍的控制平面負載，常引發連鎖崩潰 (Cascading Failures)。
    *   廣播風暴會瞬間蔓延至整個 L2 廣播域，癱瘓整座資料中心。
4.  **不可預測性 (Unpredictability)**：
    *   CPU 忙碌（如處理 ARP 風暴）導致 STP Hello 封包漏送時，鄰居會誤以為對方未運行 STP 而取消 Blocking，瞬間引發環路與廣播風暴。
    *   新加入設備若配置不當，STP Root 樹根選舉會被錯誤奪走，引發全網拓撲震盪。
5.  **缺乏靈活性與敏捷性 (Inflexibility & Lack of Agility)**：
    *   VLAN 終止於 Agg 交換器，無法跨越不同的 Agg 堆疊對，無法任意將自由埠分配給需要的 VLAN。
    *   新增或刪除 VLAN 必須全網所有節點手動配置，且 PVST 的 Hello 封包會隨 VLAN 數量倍增，嚴重拖垮控制平面，極度缺乏自動化部署敏捷性。
